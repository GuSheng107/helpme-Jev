## 二、聊天副驾：完整工作流

```text
① 用户输入：粘贴对方的话（或上传聊天截图 → 多模态 LLM 读图，系统不做 OCR）
        │
        ▼
② 上下文装配器：按优先级 + 双预算取材
   ├─ 最近 10 条消息
   ├─ 记忆条目（用户级，跨对象共享）
   ├─ 人设档案（按当前对象取：我 + 对方）
   ├─ 情绪轨迹（记忆条目 category=情绪模式）
   └─ 滚动摘要
        │  （LLM 侧预算：默认 64K 可配 / JEV 侧预算：默认 1500 字符）
        ▼
③ 翻译桥（入）：LLM 把中文上下文译成英文  ← 凡送 JEV 的内容一律先译
        │
        ▼
④ 【JEV 判断】一次请求（10 题）→ 输出对「对话者」的各种决策
   ├─ 潜台词？ / 真实意图 / 危险等级 / 该不该实质回复
   ├─ 最佳动作 / 她需要什么 / 紧张是否化解
   └─ 情绪 + 强度
        │
        ├── 信息不足（context_sufficient = 否）
        │        │
        │        ▼
        │   ⑤ LLM 生成追问 → 用户补充 → 回到 ②   【可选，轮次不设上限】
        │
        ▼
⑥ 翻译桥（出）：JEV 的英文结果转回中文展示
        │
        ▼
⑦ 人设更新：JEV 建模题（信息足够时自动更新）→ personas
        │
        ▼
⑧ 用户查看决策面板  ──【★ 用户手动触发 ★】──▶  ⑨ LLM 起草 3 条中文候选
   （也可只看决策、不要方案 = 纯分析模式）        （严格依据 JEV 的决策内容）
        │
        ▼
⑩ 【JEV 排序】对 3 条候选做优劣决策（经翻译桥）
        │
        ▼
⑪ 用户定夺：选一条 / 自己改写 / 自己写
        │
        ▼
⑫ 落库（消息 + 决策痕迹）；记忆复盘另行触发（见 §三）
```

**两条铁律**：JEV 只出决策不产文本 · LLM 只做表达不做决策。

## 三、记忆复盘工作流（与主链路解耦）

```text
触发条件（满足任一）
  ├─ 会话消息累积到阈值
  └─ 用户手动点「复盘」
        │
        ▼
LLM 读本段对话 + 现有记忆条目 + 现有人设
        │
        ▼
LLM 产出「记忆变更集」：ADD / UPDATE / INVALIDATE / NOOP
  （记忆与人设可重复存储；去重整合在这一步统一处理）
        │
        ▼
冲突仲裁：QA 对优先 > 近期证据 > 久远证据；判不了就不覆盖
        │
        ▼
写入 memory_reflections（留痕）+ 应用到 memories / personas
        │
        ▼
用户可在「记忆管理」页查看变更集并【撤销】
```

## 四、场景清单（皇上要核对的重点）

| 场景 | 定位 | 判断题集 | 人设题集 | 面板展示 |
|---|---|---|---|---|
| **恋爱助手** | 一期主力 | **人工预设 10 题**：Jarvis 7 题 + 情绪(18 类) + 强度(5 档) + 信息充足度 | 依恋类型 · 爱的五种语言 · 大五人格 | 危险等级条 / 真实意图 / 最佳动作 / 她需要什么 / 情绪强度 |
| **职场助手** | 二期 | **agent-first**：LLM 按场景描述现场生成 → 用户确认落库 | DISC · 冲突处理风格 · 大五人格 | 同结构，文案职场化（同事 / 上下级 / 客户） |
| **通用决策** | 一期 | 无固定题目，用户在「决策工作台」自由编题 | — | noul 概率条 / choice 概率条形图 / score 刻度条 |
| **自定义场景** | 二期 | 复制任一预设后编辑，或让 LLM 生成 | 同 | 复用预设面板 |

### 场景 A：恋爱助手 —— 一次完整示例

```text
【输入】她：「没怎么。」
【② 装配】最近 10 条 + 记忆（"她喜欢可颂""雷区：前任"）+ 人设（回避型依恋，置信 0.62）+ 情绪轨迹（失望→委屈）
【③ 翻译】→ "She: 'Nothing much.'" + background 英译
【④ JEV 判断】
      literal_question   = 否（有潜台词）
      true_intent        = confirm_you_care   （在试探你在不在意）
      danger_level       = 4 / 9
      should_reply_now   = 否（她要的是态度，不是一个具体安排）
      best_action        = acknowledge
      she_needs          = care
      tension_resolved   = 否
      emotion            = 委屈    intensity = 3/4
【⑥ 展示】中文面板：危险 4/9 · 真实意图「想确认你在不在意」· 最佳动作「先承认你听出来了」
【★ 用户点「生成回复」★】
【⑨ LLM 起草 3 条】
      A「我知道你说没怎么，其实是不太高兴了对吧，我听着呢。」
      B「好好，不说就不说，我陪你待着。」
      C「是不是我哪儿没做好？你跟我说说。」
【⑩ JEV 排序】A 0.52 / C 0.31 / B 0.17
【⑪ 用户定夺】选 A → 手动填入（**系统不自动发送**）
```

### 场景 B：通用决策 —— 一次完整示例

```text
【用户在决策工作台填】
  问题：「在这两个方案里，哪个更可能让老板满意？」
  题型：choice
  选项：A 先做原型快速验证 / B 先把方案文档写全
  （可点「✨ 润色」→ LLM 规范化为可判定提问 → 直接替换输入）
  上下文（可选）：填一段背景
【③④⑤】走同样的翻译桥 + JEV 请求
【结果】A 0.68（confidence 0.74）/ B 0.32  → 概率条形图，A 高亮
```

## 六、请皇上重点核对的 5 处

1. **JEV 先行**：JEV 是第一个分析者（不是 LLM 先分析），对吗？
2. **用户手动触发**：分析完先给决策，用户点一下才生成回复（也可不生成），对吗？
3. **翻译桥**：凡给 JEV 的内容都先译英文，结果再译回中文，对吗？
4. **场景清单**：恋爱（人工题集）/ 职场（LLM 生成）/ 通用决策（自由编题）/ 自定义 —— 这四个够不够？还缺场景吗？
5. **面板字段**：恋爱面板这五项（危险等级 / 真实意图 / 最佳动作 / 她需要什么 / 情绪强度）是皇上想看的吗？

---

## 七、工作流里的边界（照例说明）

- **不自动发送**：系统只填进输入框 / 给复制按钮，发送永远手动
- **不做 OCR**：图片原样交多模态 LLM
- **不接云端**：只用 SQLite，记忆治理自研
- **JEV 不含文本生成**：回复文本一律 LLM 写
