# HelpMe JEV 前端与 UI 规范

> 状态：定稿（2026-09-23）
> 技术栈固定：**React 19 + TypeScript strict + Vite + Tailwind CSS 4**（与 `human-llm-gateway` 一致，便于复用经验）。
>
> **本规范只借鉴 `human-llm-gateway` 的风格与配色，不照搬其形态**：
> 它是**桌面优先的管理后台**（表格密集、侧栏导航），本项目是**面向使用者的工具**
> （聊天副驾 + 决策工作台，**移动优先**）。

---

## 1. 体验目标

用户用这个工具做三件事：

1. **把对方的话粘进来** → 立刻看到 JEV 的判断（危险度 / 真实意图 / 最佳动作 / 她需要什么 / 情绪）
2. **在需要时**手动触发生成候选回复 → 看 JEV 排序 → **自己拍板**
3. **在通用决策工作台**里对任意问题求一个可判定的分布

三条体验原则：

- **决策要一眼看懂** —— 概率与刻度用可视化表达，不堆文字
- **移动端可用** —— 聊天副驾是"她刚发消息我想马上回"的场景，手机上必须顺畅
- **不让用户等得心慌** —— 链路有 4~5 步，必须给出**逐步进度指示**

---

## 2. 视觉方向

**继承自 `human-llm-gateway`（皇上指定）**：

- 清晰、克制、**浅色**风格；页面浅灰、卡片白色
- **主色：中等蓝 `#409eff`**；状态色**只用于表达状态与风险**
- 文字三档固定：`#303133` / `#606266` / `#909399`
- **禁止**：大面积深色背景、霓虹渐变、玻璃拟态、低对比灰字
- **禁止用巨大留白模拟营销站**
- 单一页面**最多一个** primary 按钮

**本项目相对 hlg 的调整（因为它不是后台）**：

| 维度 | hlg（后台） | 本项目 |
|---|---|---|
| 优先端 | 桌面 | **移动** |
| 信息密度 | 高（表格 44px 行高） | **中**（聊天流 + 面板，需呼吸感） |
| 圆角 | 控件 6 / 卡片 8 | 同左，但**气泡用 12** |
| 数据表达 | 表格 | **概率条 / 刻度条 / 占比排序** |
| 留白 | 极紧凑 | 略松，但仍以 4px 为基数 |

## 3. 设计 Token

集中在 `web/src/styles.css` 的 `@theme`；**业务组件不得散落重复色值**。

```css
@theme {
  /* 表面与边框 */
  --color-page: #f5f7fa;
  --color-surface: #ffffff;
  --color-surface-muted: #f8fafc;
  --color-border: #dcdfe6;
  --color-border-subtle: #ebeef5;

  /* 文字三档 */
  --color-ink: #303133;
  --color-ink-secondary: #606266;
  --color-ink-muted: #909399;

  /* 主色：中等蓝 */
  --color-primary: #409eff;
  --color-primary-hover: #337ecc;
  --color-primary-soft: #ecf5ff;

  /* 状态色 —— 只用于状态与风险 */
  --color-success: #67c23a;
  --color-warning: #e6a23c;
  --color-danger: #f56c6c;
  --color-info: #909399;

  --radius-control: 6px;
  --radius-card: 8px;
  --radius-bubble: 12px;
  --shadow-card: 0 1px 3px rgb(0 0 0 / 0.06);
}
```

### 排版

| 用途 | 规格 |
|---|---|
| 页面标题 | 20px / 28px，600 |
| 卡片标题 | 16px / 24px，600 |
| 正文 | 14px / 22px，400 |
| 辅助文字 | 13px / 20px，400 |
| 表头 / 标签 | 13–14px，500 |
| **决策数值** | 等宽字体（`.mono`），危险度 / 概率 / traceId / 模型 ID |

间距基数 **4px**；页面内边距 **16–20px**；卡片内边距 **16px**。

### 危险度配色（**本项目的核心可视化**）

`danger_level` 为 0–9 分档，**必须文字 + 颜色双表达**：

| 档位 | 语义 | 颜色 |
|---|---|---|
| 0–2 | 平和 | `success` 绿 |
| 3–5 | 有摩擦 | `warning` 橙 |
| 6–7 | 紧张 | 橙→红之间（`#f56c6c` 60% 透明度到实色） |
| **8–9** | **高风险** | `danger` 红 + **人文提示**（见 §7.3） |

## 4. 响应式与移动端（**本项目重点**）

### 4.1 断点

| 断点 | 目标 | 策略 |
|---|---|---|
| `< 640px` | **手机（主要场景）** | 单栏；抽屉 / 底部弹层承载次要内容 |
| `640–1024px` | 平板 | 可折叠侧栏；判断面板常驻 |
| `> 1024px` | 桌面 | 双栏（会话列表 + 主区） |

### 4.2 硬性要求

- **触控目标 ≥ 44×44px**（iOS HIG）；相邻可点元素间距 ≥ 8px
- **输入区固定底部**：`sticky bottom-0` + `padding-bottom: env(safe-area-inset-bottom)`（适配 iPhone 刘海/黑条）
- **软键盘不遮挡输入框**：用 `100dvh` 而非 `100vh`；必要时监听 `visualViewport`
- **输入框字号 16px**（`< 16px` 会触发 iOS 自动放大）；桌面端可为 14px
- **不依赖 hover**：触屏无 hover，所有 hover 效果必须有等价的 focus / active 态
- **禁止横向滚动**：窄屏下表格转卡片、宽内容内部滚动
- **焦点样式清晰**（`:focus-visible` 有 2px 主色描边）

### 4.3 聊天副驾的布局切换

```text
桌面 (>1024)                        移动 (<640)
┌──────────┬─────────────────┐      ┌─────────────────┐
│ 会话列表  │  判断面板        │      │  判断面板（主）  │
│ 240px    │  ─────────────  │      │  ─────────────  │
│          │  消息流          │      │  消息流          │
│          │  ─────────────  │      │  ─────────────  │
│          │  输入区(sticky)  │      │  输入区(sticky)  │
└──────────┴─────────────────┘      └─────────────────┘
                                     会话列表 → 抽屉
                                     判断面板 → 底部弹层（可上滑展开）
```

## 5. 应用框架

- 顶栏高度 **52px**（移动端同高，不放面包屑）：左侧标题 / 当前会话名，右侧用户菜单
- 桌面侧栏 **220px**（折叠 64px），白色背景 + 右边框；当前项用**浅蓝背景 + 蓝字 + 左侧 3px 主色标记**
- 主内容背景 `--color-page`
- **移动端不渲染侧栏**，改用顶部抽屉入口

## 6. 组件规范

通用组件放 `web/src/components/`；页面**不得**各写一套按钮、表单、卡片、状态标签。

### 6.1 已有原语

| 组件 | 用途 | 纪律 |
|---|---|---|
| `Button` | 按钮 | 每页最多一个 primary；危险动作红色 + 二次确认；禁用须给**原因 tooltip** |
| `Field` | 表单字段 | 标签在上；错误**贴近控件**；Secret 用 password，且**不伪造星号长度** |
| `DataCard` | 卡片容器 | 白底 + 细边框 + 8px 圆角 |
| `StatusTag` | 状态标签 | **文字 + 颜色双表达** |
| `EmptyState` | 空状态 | 必须说明**为什么为空 + 下一步做什么** |
| `Notice` | 提示条 | 状态与风险说明 |
| `PageShell` / `PageBody` / `PageHeader` | 页面骨架 | 统一内边距与标题规格 |

### 6.2 本项目特有组件（待建）

| 组件 | 用途 | 关键要求 |
|---|---|---|
| `MessageBubble` | 对话气泡 | 己方 / 对方左右分列；圆角 12px；长文本自动换行，**不撑破容器** |
| `DecisionPanel` | 判断面板 | 五项指标（危险度 / 真实意图 / 最佳动作 / 她需要什么 / 情绪）+ 每项附**信息充足度** |
| `ProbBar` | 概率条 | 用于 `choice` 结果；**数值 + 条形双表达**；排序按占比降序 |
| `ScoreScale` | 刻度条 | 用于 `score` 结果（危险度 0–9、情绪强度 5 档） |
| `ProgressSteps` | 进度指示 | 显示当前处于 **翻译 / 判断 / 起草 / 排序** 哪一步（缓解 4~5 次串行调用的等待焦虑） |
| `CandidateCard` | 候选回复卡 | 展示候选文本 + JEV 占比；点击可选用；**不自动发送** |
| `SufficiencyMeter` | 信息充足度 | 常显百分比；旁边**永远有「跳过追问，直接出结果」** |

### 6.3 交互纪律

- **用户手动触发**：分析完先给决策，**用户点了才生成候选** —— 界面上必须体现这一层（不要做成一条龙自动跑完）
- **不自动发送**：系统只填入输入框 / 给复制按钮
- **LLM 解读须标注**：可解释层的内容明确标「由 LLM 生成、仅供参考」，与 JEV 决策视觉上区分开
- 乐观更新只用于易回滚的启停动作；创建、删除、提交用**服务端确认结果**
- 加载态用**骨架屏**，不在页面中央只放一个转圈

## 7. 关键界面

### 7.1 聊天副驾

自上而下：**会话头（当前对象）→ 判断面板 → 消息流 → 输入区（固定底部）**

- 判断面板在移动端默认折叠为**摘要条**（危险度 + 最佳动作），点击展开完整五项
- 候选回复生成后，从底部弹出**弹层**展示 3 条卡片 + 占比
- 自拟方案入口常驻（用户可以完全不靠系统生成）

### 7.2 决策工作台

- 题目编辑器：题型选择（noul / choice / score）+ instructions + 选项
- 每个文本输入旁有**「✨ 润色」**入口 —— 润色后**直接替换输入**，并给一个轻量「已润色 · 撤回」提示
- 结果可视化：`noul` 概率条 / `choice` 概率条形图 / `score` 刻度条
- 移动端：编辑器与结果**标签页切换**

### 7.3 高危险度人文提示（`danger_level ≥ 8`）

面板首屏**不再是"3 条候选回复"**，而是：

> **这已超出文字回复能解决的范围，建议当面或电话沟通。**

—— 这是「诚实原则」在产品价值观上的自然延伸。

## 8. 反馈、错误与可恢复性

- 全局错误含**用户可理解的消息 + 可复制的 traceId**
- 字段校验错误放控件附近；权限错误跳 403 页；登录过期清状态并回登录页
- 错误码分流（对应后端 `code`）：
  `JEV_NOT_CONFIGURED` / `LLM_NOT_CONFIGURED` → 引导去设置页；
  `PROTOCOL_MISMATCH` → 明确告知"该端点不是 System One 协议"；
  `RATE_LIMITED` → 提示稍后重试
- 列表筛选与页码写入 URL，刷新 / 前进后退保持状态
- 重试不得重复创建资源或重复提交

---

## 9. 无障碍

- 全部交互键盘可用，焦点可见
- 图标按钮必须有可访问名称；表单有 `label`；错误与控件 `aria-describedby` 关联
- 正文与背景对比度满足 **WCAG AA**
- **状态不能只靠颜色**
- Modal / Drawer 打开时管理焦点，关闭后焦点返回触发元素
- 遵循 `prefers-reduced-motion`

## 10. 前端代码组织

```text
web/src/
├── api/            # HTTP 客户端、错误转换、各领域 API
├── components/     # Button / Field / DataCard / StatusTag / 气泡 / 面板等通用组件
├── features/       # chat / decision / personas / memories / settings
├── layouts/        # 框架、导航（含移动端抽屉）
├── routes/         # 路由与守卫
├── types/          # 跨领域基础类型
└── styles.css      # Tailwind 入口 + 语义 Token
```

规则：

- 组件不直接拼 API URL，统一走 `api/`
- 后端 Schema 的 TS 类型**一处定义**，不在页面复制
- 页面权限来自 `/api/auth/me` 的 capability，不散落角色判断
- 保持 **TypeScript strict**，不用 `any` 绕过接口变化

---

## 11. 禁止模式

- 大面积深色 / 背景近黑 / 低对比灰字
- **霓虹渐变、玻璃拟态**
- **用巨大留白模拟营销站**
- **只靠颜色表达状态**
- 每个页面各写一套按钮 / 卡片 / 弹窗 / toast
- **移动端把 hover 当唯一交互**
- 窄屏出现横向滚动
- 把完整 apiKey / Secret 渲染进表格或写入 localStorage
- 用"自动回复"这类暗示系统替用户做主的文案（应为「生成草稿 / 生成候选」）

---

## 12. 页面完成定义

一个页面同时满足以下条件才算完成：

- 权限、加载、空数据、错误、成功、并发冲突状态**完整**
- 复用语义 Token 与通用组件，浅色风格一致
- **在 390px / 1024px / 1440px 三档均可用**（键盘与触屏皆可操作）
- URL 可刷新、可前进后退
- API 类型、测试与构建通过
- **实际视觉由皇上验收** —— 构建成功不等于页面验收完成
